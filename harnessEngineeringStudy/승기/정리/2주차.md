# AI 스터디 2주차 - CLAUDE.md와 세션 관리 정리

## 1. 이번 주 핵심

이번 주 내용은 한 줄로 요약하면  
**"Claude Code를 잘 쓰려면, 규칙을 미리 정리하고 세션 오염을 관리해야 한다"**는 쪽에 가까웠다.

특히 `CLAUDE.md`는 프로젝트 규칙을 정리하는 문서이고, 실제 접근 제어나 안전장치는 별도의 설정으로 관리해야 한다는 점이 핵심으로 나왔다.

***

## 2. `CLAUDE.md`는 무엇인가?

`CLAUDE.md`는 Claude Code가 프로젝트에서 계속 참고하는 가이드 문서라고 정리할 수 있었다.

주로 아래 내용을 담는다.

- 프로젝트 코딩 컨벤션  
- 아키텍처 규칙  
- 수정하면 안 되는 영역  
- 테스트 실행 방법  
- 작업 완료 기준  

즉 `CLAUDE.md`는 프로젝트의 규칙과 판단 기준을 정리하는 문서에 가깝고, 민감한 파일 접근 차단 같은 강제 제어는 하네스나 `settings.json` 같은 환경 설정이 담당한다.

***

## 3. 메모리는 계층적으로 관리된다

자료를 보면 Claude의 메모리는 크게 네 단계로 구분된다.

- Enterprise  
  - 조직 전체 보안 정책이나 회사 공통 규칙.

- User  
  - 개인 선호, 자주 쓰는 명령, 개인 작업 스타일.

- Project  
  - 팀 공통 프로젝트 규칙과 빌드/테스트 지침.

- Local  
  - 개인 실험용, 임시 메모용, 로컬 개발 환경용 설정.

또 Auto Memory는 같은 Git 저장소 내 Worktree 사이에서 공유될 수 있어서, 상태를 개발자가 의식적으로 관리해야 한다는 점도 같이 나왔다.

***

## 4. 세션이 길어질수록 오염될 수 있다

이번 주에서 중요한 포인트 중 하나는 세션 오염 관리였다.

대화가 길어질수록 이전 작업 내용이 계속 누적되면서, 수정 범위가 불필요하게 커지거나 기존 규칙을 잊고 엉뚱한 파일을 건드릴 수 있다.

그래서 자주 나오는 명령이 두 가지였다.

- `/clear`  
  - 현재 대화를 초기화하고 새 작업처럼 다시 시작하는 것.

- `/compact`  
  - 기존 대화를 요약해서 핵심만 남기는 것.

`/compact`를 사용할 때는 변경 파일, 실행 명령, 테스트 결과, 남은 작업 같은 내용을 같이 요약하게 해야 정보 유실을 줄일 수 있다는 점도 정리돼 있었다.

***

## 5. 좋은 프롬프트는 범위를 명확히 한다

AI가 엉뚱한 파일을 수정하는 경우는 대부분 모델 자체의 문제가 아니라, 지시 범위와 검증 기준이 모호해서 생긴다고 정리할 수 있었다.

그래서 작업을 요청할 때는 최소한 아래 내용을 함께 적는 게 중요하다고 나왔다.

1. 해결해야 하는 문제를 한 문장으로 정의하기.
2. 수정 가능 범위와 수정 금지 범위를 분리해서 적기.
3. 절대 깨지면 안 되는 조건 적기.
4. 무엇을 만족해야 완료인지 기준 적기.

그리고 큰 작업은 바로 구현부터 시키기보다, 먼저 계획부터 세우게 하는 쪽이 더 안전하다는 점도 같이 나왔다.

***

## 6. 자동화와 Worktree 운영

Claude Code는 반복 작업 자동화에는 잘 맞지만, 최종 판단까지 완전히 맡기면 안 된다는 점도 반복해서 나왔다.

예를 들면 Issue 분석, 브랜치 생성, 코드 초안 작성, 커밋, Draft PR 생성 같은 부분까지는 자동화할 수 있지만, 코드 리뷰나 CI 확인, Merge 승인은 결국 사람이 해야 한다.

또 병렬 작업을 할 때는 같은 디렉터리에서 여러 세션을 돌리기보다 Worktree를 분리해서 쓰는 쪽이 더 안전하다는 내용도 같이 나왔다. 그래야 파일 충돌, 테스트 충돌, 컨텍스트 혼선을 줄일 수 있다.

***

## 7. 기억할 포인트

이번 주 내용을 정리하면 아래 정도로 묶을 수 있다.

1. `CLAUDE.md`는 프로젝트 규칙을 정리하는 문서다.
2. 강제 차단은 `CLAUDE.md`가 아니라 설정과 권한 정책이 맡는다.
3. 세션이 길어질수록 컨텍스트 오염이 생길 수 있으니 `/clear`, `/compact`를 적절히 써야 한다.
4. 프롬프트에는 수정 범위, 금지 범위, 완료 기준을 분명히 적어야 한다.
5. 자동화는 구현 보조까지이고, 최종 리뷰와 Merge는 사람이 담당해야 한다.
6. 병렬 작업은 Worktree를 활용하는 쪽이 더 안전하다.
